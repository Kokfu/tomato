# V8.1 landmark regression: four failing landmark tests

Scope: the four browser tests in `tests/e2e/landmarks.spec.ts` that failed in the V8.1 run (and on V8.0.1 too).
No landmark was remodelled or moved, and no rendering, streaming or V8.1 performance code changed.

## Finding

**No landmark is missing, hidden by mistake, misplaced or duplicated in the default V7 world. The four failures
came from an outdated test expectation, not from an application defect.**

The four sites in the landmark registry (`landmark-sites.json`) can be drawn by two renderers:

| Site | Default V7 world (mode `c`) | V4 mode (key 1) |
|---|---|---|
| Hiang Thian Siang Ti Temple | V5 section model `models/v5/temple.lod0.glb` (23,877 triangles) | registry `models/landmarks/…/lod0.glb` or `lod1.glb` |
| Lau Ya Keng Food Court | V5 section model `models/v5/foodcourt.lod0.glb` (12,747 triangles) | registry |
| Yang Choon Tai opera stage | V5 section model `models/v5/stage.lod0.glb` (1,266 triangles) | registry |
| Carpenter Street Harmony Arch | registry, streamed with distance LOD | registry |

The V5 section models were reconstructed from photographs in V5 (`docs/V5_REPORT.md` section 6). The section
draws them at the same anchors as the registry. While the section is shown, `V5Controller.setMode` adds exactly
these three ids to `LandmarkModels.hidden`, so the registry does not load a second copy. That is the intended
architecture: V7 Jalan China, plus the V5 custom landmarks, plus V8 driving.

All four tests waited for `landmarkModels.info()` to report the same LOD for **every** registry site. Since the V8
UI cleanup (`11f810c`), the game starts in V7, so the three hidden sites always report -1. The wait timed out after
60 s, before the tests checked any landmark, collision or walking behaviour. The fifth test (Harmony Arch) only
checks the arch, so it passed.

| Failing test | Landmark involved | State in default V7 | Model exists and loads | Why the test expected it | Verdict |
|---|---|---|---|---|---|
| load only near the landmark, switch LOD … | all four | temple, food court and stage drawn by the V5 section; arch streamed by the registry | yes, all four | written for V4, where the registry drew every site | outdated expectation |
| the player walks into the forecourt and the food court … | temple, food court, stage | drawn by the V5 section; registry collision active | yes | the same wait before walking | outdated expectation; the walking checks pass |
| the street past the landmarks stays walkable … | all four | as above | yes | the same wait | outdated expectation |
| graphics presets never remove landmark geometry | all four | as above, at low, medium and high | yes | the same wait at every preset | outdated expectation |

## Checked in the browser (default V7, Edge with GPU)

- The three V5 section models sit within 0.01 m of the registry anchors, with the same yaw and scale 1.
- The registry holds no copy of them, so each site is drawn exactly once. The arch streams LOD 1 at the spawn,
  LOD 0 near and nothing far away.
- Collision is unchanged: the temple forecourt and the food court aisle are open, and the temple hall and the stage
  are solid. It comes from the registry's site collision, which applies in every mode.
- The landmark guard is empty: no generic building extrusion was generated for a protected landmark.
- The V7 exclusion list replaces only the Carpenter Street blocks, the three temple-area placeholder records and the
  Jalan China block (`src/v5/geo.ts`). It shares no building id with the other custom landmarks (DUN, Fort
  Margherita, Astana, Tua Pek Kong, Borneo Cultures Museum, Square Tower, Old Courthouse, Floating Mosque, Darul
  Hana Bridge). All of these were checked through the OP landmark teleport in V7 and rendered.

## Changes

- `src/v5/V5Scene.ts`: each V5 section landmark model now carries `userData.landmark = <site id>`, the tag the
  registry already gives its own models. Tests can then check the one-copy-per-landmark rule across both renderers.
  This changes no behaviour.
- `tests/e2e/landmarks.spec.ts`:
  - The tests still run in the default V7 world. None was switched to V4.
  - The wait now requires the registry's LOD for the sites it is responsible for, and the section's own model for
    the other three.
  - New `expectOneEach` check: every site is drawn exactly once, by the expected renderer, on its anchor, at the
    shipped full-detail triangle count (section models are checked against `models/v5/manifest.json`).
  - Only the registry's own sites may fetch a full model, so a hidden duplicate in flight now fails the test.
  - New test: switching V7 → V4 → V7 hands the three sites from the section to the registry and back, never with
    two copies. In V4 the registry draws all four at full detail.

Mutation check: with the `hidden` handover removed from `V5Controller.setMode` (the registry draws a second copy),
the LOD test fails.

## Results

- Landmark tests 6 of 6 pass in default V7 (5 restored plus the new mode-handover test).
- Focused e2e (driving, OP mode, gameplay, district, landmarks, production): 32 of 32 pass.
- Unit 65 of 65 pass, `tsc` is clean, and `vite build` succeeds.

**The V8.1 performance gain holds.** Cold high-speed run (`tools/dev/drive-bench.ts --scenarios=D --runs=1`, fresh
browser, production builds, Intel UHD / Edge, medium preset). Runs alternated between the two builds in one
session; the V8.1 build includes the change above.
